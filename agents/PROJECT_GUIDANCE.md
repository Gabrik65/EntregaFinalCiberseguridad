# Contexto del proyecto

La [especificación P1](../docs/Especificación%20del%20proyecto%20P1.txt) es la fuente principal de requisitos y evaluación. Léela antes de afirmar que el proyecto cumple la entrega. Trabaja solo en `EntregaFinal`; no modifiques tareas anteriores.

El proyecto Python contiene Miner, Analyzer, Visualizer y Reporter. Ejecutar `main.py` sin argumentos abre la GUI Tkinter; `--no-gui` ejecuta el flujo completo en una terminal y los subcomandos existentes siguen disponibles. `support/interface/` contiene la ventana, el cargador local de Tkinter y el coordinador. `support/scripts/install_tkinter.py` instala Tkinter dentro de `.venv` sin `sudo` en Ubuntu x86_64. Miner selecciona hasta 50 repositorios públicos elegibles de NestJS y fija sus revisiones antes de usar CodeQL, Syft y Grype. Analyzer prepara los datos y ejecuta un notebook con categorías basadas en el lenguaje principal. Visualizer crea HTML local. Reporter analiza una copia de este proyecto y genera un informe validado, simulado o mediante OpenRouter.

El Dockerfile de la raíz instala Python y las herramientas externas dentro de la imagen. `compose.yaml` monta el proyecto para compartir ejecuciones guardadas entre contenedores. `.devcontainer/devcontainer.json` construye ese mismo Dockerfile. Las rutas de herramientas pueden configurarse con `ICC610_TOOLS_DIR`; las ejecuciones locales usan `.tools/` por defecto. El punto de entrada de Docker prepara y actualiza la base persistente de Grype para comandos que requieren análisis. La GUI ofrece ejecución completa y botones de Miner, Analyzer, Visualizer y Reporter; utiliza `runs/nestjs/` como ejecución activa de Miner y la detecta al reiniciarse, sin lista desplegable. Reutiliza registros solo si coinciden nombres, commits, categorías y configuración; procesa los pendientes de la muestra guardada. El flujo completo exporta Miner antes de ejecutar Reporter. Reporter está disponible sin Miner y examina este proyecto. La GUI confirma antes de cerrar durante una ejecución activa; al confirmar, la ejecución se interrumpe y puede quedar incompleta. El usuario realiza las comprobaciones con Docker Compose; no ejecutes Compose desde el agente.

El código se divide entre `miner/`, `analyzer/`, `visualizer/` y `reporter/`; `support/core/` contiene modelos compartidos, persistencia, procesos y exportación. `results/` contiene exportaciones portables, nunca código Python. Conserva las importaciones y rutas relativas a la raíz al mover módulos.

`data/run-config.json`, la GUI y `--no-gui` usan un límite predeterminado de 50. La API de GitHub devolvió 53 repositorios públicos de NestJS el 9 de octubre de 2026; dos son forks, así que 51 cumplen el filtro actual. El manifiesto de NestJS se genera al iniciar y se guarda dentro de la ejecución; las ejecuciones anteriores de Fastify, Grafana y freeCodeCamp son históricas y ya no se usan por defecto. La organización de la GUI es fija y de solo lectura. `runs/` guarda ejecuciones y evidencia; `results/` guarda exportaciones portables. Conserva artefactos originales, hashes, revisiones y estados independientes por herramienta. Un fallo o un lenguaje no compatible no significa cero vulnerabilidades.

No ejecutes instalaciones npm ni scripts de repositorios analizados. Nunca incluyas credenciales en código, registros, resultados ni Git. Limpia solo archivos temporales y copias creados por las ejecuciones propias del proyecto. Mantén legibles los contratos de resultados y la evidencia anterior.

Tras cambios de código, ejecuta `.venv/bin/python -m pytest -q`, `.venv/bin/python -m pip check` y `.venv/bin/python main.py --help`. `pytest.ini` limita el descubrimiento a `support/tests/` para evitar las copias de Reporter en `runs/`. No repitas análisis costosos de repositorios solo para comprobar importaciones. Comunícate brevemente en el idioma del usuario y no delegues sin petición explícita.
